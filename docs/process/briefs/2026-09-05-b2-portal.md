## The aggregate (§3.3, §5.7, §11.8)

- `PortalIdentity` record: `id` (`EntityType.PORTAL_USER`, prefix `ptu_`),
  `clientId`, `email` (lower-cased + trimmed at construction), `name`
  (null ⇔ blank), `passwordHash` (null until a reset completes), `status`
  `ACTIVE|DISABLED` (enum with `parse`), `source` `INVITE|JIT` (enum),
  `lastLoginAt`, `createdAt`, `updatedAt`. `canSignInWithPassword()` =
  ACTIVE and a non-empty hash. Transitions as §11.8.
- `PortalIdentityRepository`: `findById`, `findByClientAndEmail(clientId,
  email)`, `findByClient(clientId)` newest first, `persist(identity, tx)`
  = upsert `ON CONFLICT (client_id, email) DO UPDATE SET name, status,
  updated_at` (a re-ensure keeps id / source / created_at / password),
  `delete(identity, tx)`, `touchLastLogin(id)` (best-effort autocommit),
  `setPasswordHash(id, hash, tx)` (the reset unit will call it).
- Operations (all `Authorize: Public` — the controller gates), events
  under source `platform:portal`, subject `platform.portal-identity.<id>`,
  message group `platform:portal-identity:<id>`:
  - `Ensure{clientId, email, name?, source}` → `CLIENT_ID_REQUIRED`,
    `EMAIL_REQUIRED`, `EMAIL_INVALID` (an `@` at index > 0 and not last);
    client missing → `Client_NOT_FOUND` 404 (use `ClientRepository`);
    existing row → `ACTIVE`, name overridden only when non-blank; new →
    ACTIVE; event `platform:portal:identity:ensured` `{identityId,
    clientId, email, created, source}`.
  - `SetStatus{id | clientId+email, status}` → `TARGET_REQUIRED`,
    `STATUS_INVALID`; not found → `PortalIdentity_NOT_FOUND`; a `clientId`
    that differs from the row's is the same 404 (cross-client hidden);
    event `platform:portal:identity:status-set` `{identityId, clientId, status}`.
  - `Delete{clientId, id}` → `ID_REQUIRED`; 404 rules as above; event
    `platform:portal:identity:deleted` `{identityId, clientId, email}`.
  Remember: event records must never shadow a `DomainEvent` accessor
  (`principalId()` is the actor) — `DomainEventContractTest` enforces it.

## `/api/portal-users` (§5.7 table; lockfile shapes)

Authorization: `Checks.requirePortalUserView(ac, clientId)` for GET,
`Checks.requirePortalUserManage(ac, clientId)` for the rest (they exist in
`shared/auth/Checks.java`).

- `POST /api/portal-users` `PortalUserRequest{clientId*, email*, name?,
  returnInviteLink?, redirectUri?}` → `CLIENT_ID_REQUIRED`; `redirectUri`
  (trimmed) must exactly equal a registered redirect URI of one of the
  client's **portal-flagged** OAuth clients (`OAuthClientRepository.findAll`
  filtered by `portalClientId()`; `REDIRECT_URI_INVALID` 400); absent ⇒
  `defaultPortalRedirect` = the first parseable, non-wildcard registered
  URI's `scheme://host/`, else null. `Ensure(INVITE)`; re-read. Then:
  **SSO-owned domain** (an OIDC `IdentityProvider` whose derived
  `allowedEmailDomains` contains the email's domain, case-insensitive scan
  of `IdentityProviderRepository.findAll`): no set-password step —
  `returnInviteLink` ⇒ `inviteUrl` = redirectUri or the default origin,
  else `PortalInviteEmailer.sendPortalSsoInvite(email, target)` when a
  target exists (`invited=true` on success); otherwise, **only while the
  identity has no password**: `returnInviteLink` ⇒ `inviteUrl =
  emailer.inviteLink(identity, target)` (`INVITE_LINK` 500 on failure),
  else `emailer.sendPortalInvite(identity, target)` (`INVITE_EMAIL` 500).
  Response `PortalUserResponse{identityId, created, invited, inviteUrl?,
  ssoManaged?, hasPassword}`.
- `GET /api/portal-users?clientId=` → `CLIENT_ID_REQUIRED`; `{portalUsers:[{identityId,
  email, name, status, source, hasPassword, lastLoginAt?, createdAt, updatedAt}]}`.
- `POST …/{id}/activate` / `deactivate` body `{clientId*}` → `{message:"Portal user activated"|"Portal user deactivated"}`.
- `DELETE …/{id}?clientId=` → `{message:"Portal user deleted"}`.

`PortalInviteEmailer` is an interface you define with a `logging()`
default (like `principal.InviteEmailer`): `sendPortalInvite(identity,
target)`, `sendPortalSsoInvite(email, target)`, `String inviteLink(identity,
target)` (the logging one returns `target + "?invite=" + identity.id()`
so the link path is testable; the real reset-token link lands with the
password-reset unit). Wire `PortalInviteEmailer.logging()` in Platform.

## Portal auth endpoints (§3.2, §5.1–§5.5)

- `PortalLoginFlow` over `portal_login_flows` (`id` `plf_`? — check
  `EntityType`; if no prefix exists use `EntityType.PORTAL_LOGIN_FLOW` only
  if present, otherwise add the enum constant with prefix `plf`), fields
  `oauthClientId, portalClientId, redirectUri, scope?, state, nonce?,
  codeChallenge?, codeChallengeMethod?, createdAt, expiresAt` (10 min).
  Repository: `insert`, `findLive(id)` (absent when expired), `consume(id)`
  = `DELETE … WHERE id = ? AND expires_at > now() RETURNING`.
- `GET /portal/authorize` exactly as the §5.1 table (direct errors in the
  OAuth shape via `auth.oauth.OAuthError`; post-validation errors 307 to
  `redirect_uri` with `error&error_description&state`; `RedirectUriMatcher.matches`
  for the URI; ok ⇒ 307 to `/portal/login?flow=<id>`).
- `POST /portal/auth/check-domain` (§5.2), `POST /portal/auth/login`
  (§5.3, the numbered table is the order), `POST /portal/auth/password-reset`
  (§5.4 — the mail send is a `PortalInviteEmailer.sendPortalReset(identityId,
  email, origin)` call you add to the interface; errors swallowed; always
  200). The cluster bucket is `RateLimit.enforce(store, RateLimit.Bucket.PORTAL_LOGIN,
  key, policies.portalLogin())` — check the bucket enum name; it fails open
  by construction. Password check: `PasswordHash.matches`; the uniform 401
  path calls `PasswordHash.equalizeTiming(password)` first. `IssueCode`
  (§5.5): `AuthorizationCode.issue(flow.oauthClientId(), identity.id(),
  flow.redirectUri(), now)` + `withScope/withNonce/withState/withPkce`,
  `GrantStore.insert`; response `{"redirectUrl": redirect_uri + ?/& +
  code=…&state=…}` — **no cookie**.

## Tests (TestHttp over the embedded Postgres)

`PortalIdentityTest` (entity transitions, email normalisation),
`PortalIdentityRepositoryTest` (the upsert keeps id/source/created_at/
password; cross-client isolation), `PortalIdentityOperationsTest` (events
+ audit rows through `UnitOfWork`), `PortalUserApiTest` (lockfile shapes,
the SSO-domain branch: `ssoManaged`, never a set-password invite, the
invite link on an SSO domain is the portal origin — Go pins this),
`PortalAuthApiTest` (the §5.3 journey: authorize → flow → login → code
redirect whose `code` redeems from `GrantStore.findCode` with subject
`ptu_…`; suspended identity = uniform 401 and the flow is **not**
consumed; an SSO-owned domain refuses the correct password with 401
`SSO_REQUIRED`; the 11th attempt in 15 min is 429; password-reset is a
silent 200 for unknown and SSO addresses).

Mutants to run and report as killed:
1. `SetStatus` ignores the `clientId` mismatch (cross-client 404) → its test fails.
2. `persist` upsert overwrites `source`/`password_hash` → the repository test fails.
3. `/portal/auth/login` consumes the flow before the password check → the suspended-identity test (flow still live) fails.
4. `/portal/auth/login` skips the SSO-domain refusal → its test fails.
5. `/portal/authorize` accepts a non-portal client → its test fails.
6. `POST /api/portal-users` sends a set-password invite on an SSO domain → its test fails.

Run: `export JAVA_HOME=$(mise where java)`;
`mvn -q -pl server test -Dtest='Portal*Test,LockfileCoverageTest,ServerTest' -Dsurefire.timeout=300`
then the full `mvn -q -pl server clean test -Dsurefire.timeout=600` once.
`-Werror` is on (Jackson 3: `asString()`, never `asText()`). Never
`mvn install`. Never two Maven runs at once.
