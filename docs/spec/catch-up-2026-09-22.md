## Slice C2 — the connection's service account signs; never unsigned silently

`DeliveryCredentials` (server `platform/dispatchjob/processing` / wherever `41d718cb` put it):

- **Resolution order** exactly as the hand-off §Resolution order: (1) `subscription.serviceAccountId`,
  (2) `subscription.connectionId → connection.serviceAccountId`, (3) the application's oldest
  active account via `subscription.applicationCode` or the direct job's code first segment,
  (4) bare **with a reason**. Steps 1–2 resolve **by id**, require `active`, and **never fall
  through** past a named account: inactive / missing / no webhook credentials ⇒ no credentials and
  the reason naming `<who>` (`subscription <code>` / `connection <code>`), exactly the wording in
  the hand-off's table. A by-id cache beside the by-application one, same 1-minute memo.
- `Resolved` gains `reason` (non-empty exactly when both credentials are empty) and `signedBy` (the
  service-account code).
- Processing: WARN `dispatch process: delivering unsigned` with `job_id`, `subscription_id`,
  `reason`; a **failed** attempt's `errorMessage` gains `" (delivered unsigned: <reason>)"`;
  success and deferral untouched. No secret in any log/message/exception/toString — unchanged.
- **Failed attempts keep the response body** (`response_body` stored on failure too).
- **`request_info`** on every attempt: `{signedBy, signature: bool, bearer: bool, timestamp,
  names: [sorted header names], unsignedReason, target}` — never a secret; exposed as `request` on
  the attempt DTO.
- **401/403 ⇒ `FAILED` on the first attempt** (the same credentials cannot succeed on retry), logged
  `dispatch failed (subscriber refused credentials; not retried)`; `attempt_count` behaviour
  unchanged (the hand-off's note).
- Signature bytes unchanged: `HMAC-SHA256(secret, ts + body)`, `ts` as `yyyy-MM-dd'T'HH:mm:ss.SSS'Z'`,
  sent verbatim in `X-FlowCatalyst-Timestamp` (catch-up §B) — pin that the Java signer's bytes match
  a fixed vector shared with Go's test (`TestProcess_SignsSubscriberDelivery` — take its vector).

## Slice C4 — router: a deferred copy keeps its in-flight entry (catch-up §A.1)

`InFlightTracker` + `Pool`'s deferral path, exactly the hand-off's list: a deferral **marks**
(`deferredUntil`) instead of removing; a copy under a **different** broker id for a deferred message
⇒ external requeue ⇒ the caller ACKs (deletes) it; the deferred copy itself returning (same or blank
broker id) ⇒ new, after clearing the mark and adopting the fresh receipt; `count()` excludes deferred
entries, `deferredCount()` reports them; the reaper's idle rule skips a deferred entry until
`deferredUntil + 5 min`, the absolute ceiling (2 h) still applies; the mark is set even when the
broker's `defer` call fails; a message with no consumer to defer to is removed as before.
**Budget default 5,000 → 15,000** (HOL addendum), the pause warning states the budget and the remedy.
