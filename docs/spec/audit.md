# Audit log — behavioural spec

The contract for `io.flowcatalyst.platform.audit`. Derived from the lockfile
(`/api/audit-logs*` — nine read operations) plus the filter, ordering,
pagination and authorization rules the read API embodies. The Java is
written *from* this; tests assert it. Questions marked **load-bearing or
accident?** need an owner ruling — until ruled on, the behaviour is kept.

## 1. Aggregate

An audit log entry is the platform's memory of *who asked for what*: one row
per use case run, written by the unit-of-work sink in the same transaction as
the aggregate change and the domain event (`docs/usecase-envelope.md`, "What
the audit row contains"). This package is **read-only**: it has no
operations, no events and no `Persist` — rows enter `aud_logs` only through
`PlatformSink.writeAudit` (and, later, the SDK batch-ingest endpoint
`POST /api/audit-logs/batch`, which is a separate unit and is **not** part of
this surface).

| Field | Type | Source column | Notes |
|---|---|---|---|
| `id` | `aud_` + 13-char TSID | `id` | generated by the sink |
| `entityType` | string | `entity_type` | second subject segment, capitalised (`platform.eventtype.evt_1` → `Eventtype`) |
| `entityId` | string | `entity_id` | third subject segment |
| `operation` | string | `operation` | the command record's simple class name (`CreateCommand`, `UpdateCommand`…) |
| `operationJson` | JSON document, optional | `operation_json` (JSONB) | the command as JSON; absent when the column is `NULL` or the JSON literal `null` |
| `principalId` | string, optional | `principal_id` | the acting principal; `NULL` for unauthenticated/system runs |
| `principalName` | string, optional | `iam_principals.name` via `LEFT JOIN … ON id = principal_id` | **derived on read**, never stored; absent when the principal is unknown or the row has no principal |
| `applicationId` | string, optional | `application_id` | `NULL` from the sink today |
| `clientId` | string, optional | `client_id` | `NULL` from the sink today |
| `performedAt` | timestamp | `performed_at` | the event's time |

No state machine; no transitions; the record only refuses `null` in its
required components.

## 2. HTTP surface (lockfile)

Every route is `GET`, gated in the handler by `Permission.AUDIT_LOG_VIEW`
(`platform:admin:audit-log:view`; anchors always pass). Unauthenticated →
403 `UNAUTHENTICATED`; missing permission → 403 `PERMISSION_REQUIRED`
(`permission required: platform:admin:audit-log:view`). Every error is the
`ErrorModel` envelope. The literal segments (`recent`, `entity-types`,
`operations`, `application-ids`, `client-ids`, `entity/…`, `principal/…`) are
registered before `{id}` so they win.

| Method / path | Query / path inputs | Success | Envelope |
|---|---|---|---|
| `GET /api/audit-logs` | `after`, `pageSize`, `entityType`, `entityId`, `principalId`, `operation`, `applicationIds` (CSV), `clientIds` (CSV) | 200 | **cursor** `AuditLogListResponse` `{auditLogs[], hasMore, nextCursor?}` |
| `GET /api/audit-logs/recent` | same — an exact alias of the list | 200 | cursor, as above |
| `GET /api/audit-logs/entity-types` | — | 200 | `AuditLogEntityTypesResponse` `{entityTypes[]}` |
| `GET /api/audit-logs/operations` | — | 200 | `AuditLogOperationsResponse` `{operations[]}` |
| `GET /api/audit-logs/application-ids` | — | 200 | `AuditLogApplicationIDsResponse` `{applicationIds[]}` |
| `GET /api/audit-logs/client-ids` | — | 200 | `AuditLogClientIDsResponse` `{clientIds[]}` |
| `GET /api/audit-logs/entity/{entityType}/{entityId}` | path | 200 | `AuditLogListResponse` `{auditLogs[], hasMore: false}` — **not paginated**, first 500 |
| `GET /api/audit-logs/principal/{principalId}` | path | 200 | `AuditLogListResponse` `{auditLogs[], hasMore: false}` — not paginated, first 500 |
| `GET /api/audit-logs/{id}` | path | 200 | `AuditLogResponse`; 404 `AuditLog_NOT_FOUND` `AuditLog not found: <id>` |

Wire shapes:

| Schema | Fields (in order) | Notes |
|---|---|---|
| `AuditLogResponse` | `id, entityType, entityId, operation, operationJson?, principalId?, principalName?, applicationId?, clientId?, performedAt` | optional fields omitted when absent; `performedAt` RFC 3339, 6 fractional digits, `Z` |
| `AuditLogListResponse` | `auditLogs[]`, `hasMore`, `nextCursor?` | `auditLogs` never `null`; `nextCursor` omitted unless `hasMore` |
| `AuditLog{EntityTypes,Operations,ApplicationIDs,ClientIDs}Response` | one string array | never `null` |

`operationJson` is a **JSON string on the wire**, not a nested object: the
command document compacted (no insignificant whitespace) and then emitted as
a string, because the SPA stores it as `string | null` and `JSON.parse`s it
itself. A `NULL` column or a JSON `null` literal is omitted. (The JSONB
column normalises the stored bytes — `{"k": "v"}`, keys re-ordered shortest
first — so the compaction is what keeps the wire stable across writers; the
key order on the wire is Postgres's, not the command record's.)

## 3. The cursor list (`/api/audit-logs`, `/recent`)

| Input | Rule |
|---|---|
| `pageSize` | absent → 50; `< 1` or `> 200` → **50** (not clamped to 200 — the lockfile's "capped at 200" wording and the code disagree: **load-bearing or accident?** open question 1); non-integer → 400 `VALIDATION` with `details.errors[{message: "invalid integer", location: "query.pageSize", value}]` |
| `after` | absent/empty → first page; otherwise an opaque cursor (§4); malformed → 400 `CURSOR` `invalid cursor` |
| `entityType`, `entityId`, `principalId`, `operation` | equality filters; absent/empty → no filter |
| `applicationIds`, `clientIds` | comma-separated; each part trimmed, blanks dropped; the remaining values form an `IN` filter; absent/empty/all-blank → no filter |

Ordering: `performed_at DESC, id DESC` — newest first, id as the tiebreak so
the order is total and the keyset is stable.

Pagination: the repository is asked for `pageSize + 1` rows; if it returns
more than `pageSize`, `hasMore = true`, the extra row is dropped and
`nextCursor` encodes the position of the last *returned* row. Otherwise
`hasMore = false` and `nextCursor` is omitted. An empty page has
`hasMore = false`.

`principalName` is joined for every row of every list.

## 4. Cursor format (`AuditLogCursor`)

A keyset position `(performedAt, id)`. Encoded as base64url **without
padding** of the text `<performedAt as RFC 3339 UTC>|<id>`; decoding splits
on the first `|`, parses the timestamp leniently (0–9 fractional digits, as
both the Go and the Java writer may have produced), and treats any failure —
bad base64, no `|`, unparseable time, an empty id after the `|` (no row has
one, so it is never a position) — as one validation error: 400 `CURSOR`
`invalid cursor`. The encoder writes the timestamp with `ISO_INSTANT`
(0/3/6/9 fractional digits); the stored value has microsecond precision, so
a round trip is exact. The next page is every row with
`(performed_at, id) < (cursor.performedAt, cursor.id)` in the same ordering.

A cursor is opaque to clients: its only consumer is this endpoint.

## 5. The filtered lists (`/entity/…`, `/principal/…`)

Both use the offset-style repository read with **no cursor and no offset**:
`entity/{entityType}/{entityId}` filters on both path values, `principal/{principalId}`
on the principal id; limit 500; ordering `performed_at DESC` (id is not a
secondary key here — **accident?** open question 2: the cursor list and this
list order ties differently; harmless because no keyset is derived from this
list). The response is the list envelope with `hasMore = false` and no
cursor — the same `AuditLogListResponse` schema, not a separate shape.

The repository's filter for this read also supports `clientId`, `since`
(`performed_at >= since`) and `until` (`performed_at <= until`) and an offset
— none of which any route passes today (open question 3).

## 6. Facets (`/entity-types`, `/operations`, `/application-ids`, `/client-ids`)

Each returns the **distinct non-null** values of one column, ascending,
at most 500. The column set is closed (`entity_type`, `operation`,
`application_id`, `client_id`) — a typed enumeration in Java, never a column
name from the wire. With the sink writing `NULL` application/client ids, the
last two are empty lists until another writer fills those columns.

## 7. Repository guards (constants)

| Guard | Value | Load-bearing or accident? |
|---|---|---|
| cursor read: limit `<= 0` or `> 501` → 101 | 101 = 100 + 1 over-fetch | accident of "100 default, +1 for hasMore"; unreachable from the API (which always passes 2..201) |
| filtered read: limit `<= 0` or `> 500` → 100 | | same family; the API passes 500 |
| facet read: limit `<= 0` or `> 1000` → 200 | | same family; the API passes 500 |
| API page size: absent / `< 1` / `> 200` → 50 | | see open question 1 |
| API filtered-list limit | 500 | |
| API facet limit | 500 | |

Invalid limits are *corrected* by the repository rather than rejected
(open question 4).

## 8. Authorization placement

| Where | What |
|---|---|
| Handler | `Checks.require(Auth.current(), AUDIT_LOG_VIEW)` on every route |
| Use case | none — there are no use cases |
| Resource-level | **none**: a viewer sees every row regardless of client scope (open question 5) |

## 9. Persistence

None in this package. The rows are written by `PlatformSink.writeAudit`
(see `docs/usecase-envelope.md`) and the tests seed them through a real
`UnitOfWork.emitEvent`, so what is read back is genuine sink output.

## 10. Open questions for the owner (summary)

1. `pageSize > 200` resets to 50 rather than clamping to 200. Lockfile text
   says "capped at 200". Keep the reset (pinned by test) or clamp?
2. The filtered lists order by `performed_at DESC` only; the cursor list adds
   `id DESC`. Align the filtered lists to the total order?
3. `clientId` / `since` / `until` / offset exist in the repository filter but
   no route passes them. Keep (SDK/BFF may) or drop?
4. The repository silently corrects out-of-range limits. Keep or make them
   programming errors (`IllegalArgumentException`)?
5. No client-scope visibility on audit rows: any principal holding
   `audit-log:view` sees every client's rows. Intended (the permission is a
   platform-admin one) or accident?
